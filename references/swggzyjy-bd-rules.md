# 标段录入的校验规则与取值口径

规则有两个来源，**两个都要读**：

- **控制器**：`web/jyzxt/jsgcjy/gkzb/jysq/Jsgczbxmbdbjcly.java` 的 `doValidate`（226 行起）。
  与本单据强相关的硬校验在这里。
- **service**：`custom/service/jsgczb/JsgcbdbjService.java` 的 `validateNormal`（233 行起）、
  `validateFJSZ`（486 行起）。按项目类型分支的通用规则在这里。

另注意 `doValidate` 的 `zbxmlx` / `zblx` 取自 **URL query string**
（`request.getParameter("zbxmlx")`），`dbms` 取自 `request.getParameter("queryString$dbms")`。
URL 缺这些参数 → `getShowAllTab(null,null)` 返回 false → **按项目类型分支的校验整段被跳过**。
换项目要重新读这两个 service——汕尾的规则不一定适用于云浮/韶关。

## 控制器里的硬校验（汕尾 A01 房建实测）

| 约束 | 规则 | 报错文案 |
|---|---|---|
| 合同估算价 ≤ 招标控制价 | `htgsjy.compareTo(zbkzjy) > 0` 即报错 | "合同估算价须小于或等于招标控制价" |
| 招标文件份数 | 必须恰好 1 份 | "请上传招标文件（单份）" / "招标文件数量为一份" |
| 招标范围及规模 | `zbfw` **汉字数** ≥ 50 | "招标范围及规模至少填写50个汉字" |
| 招标内容 | `jsnrhgm` **汉字数** ≥ 50 | "招标内容至少填写50个汉字" |
| 标段分类个数 | 最多 3 个 | "标段分类 最多只能选择3个" |
| 标段名称长度 | ≤ 200 字 | "标段名称最长可输入长度为200字" |
| 项目状态 | 特定状态禁止编辑 | "项目状态不符，操作失败" |

"汉字数"是 `jsgcxmsqService.outPutChineseCount()` 的结果，只数中文，
标点与英文不计入——写长文时别用英文缩写凑数。

## service 里按项目类型分支的规则

`showAllTab = getShowAllTab(zbxmlx, zblx)`，房屋建筑(C_FWJZ)/市政(C_SZ)/其他(C_QT)/
水利(C_SL)/公路(C_GL)/水运(C_SY) 均为 true。showAllTab=true 时：

| 约束 | 规则 | 触发文案 |
|---|---|---|
| 评标委员会人数 | 5~50 且为单数 | "评标委员会人数为5~50内的单数" / "评标委员会人数为单数" |
| 定标委员会人数 | ≥7 且为单数 | "定标委员会人数为大于等于7的单数" |
| 资格条件 | ≥1 条 | "至少录入1个资格条件" |
| 资格条件内容要求 | 每条必填 | "资格审查内容要求必须填写" |
| 形式评审项 | ≥1 条 | "至少录入1个形式评审、响应性评审项目" |
| 形式评审内容要求 | 每条必填 | "形式评审内容要求必须填写" |
| 报价类型为下浮率类 | 需填下浮率保留位数 | "请选择下浮率保留位数" |

评标办法 = **06 定性评审** 时额外要求：

| 约束 | 规则 | 触发文案 |
|---|---|---|
| 技术评审项 | ≥1 条 | "至少录入1个技术评审项" |
| 技术评审说明 | 每条必填 | "技术评审说明必须填写" |
| 商务评审项 | ≥1 条 | "至少录入1个商务评审项" |
| 商务评审说明 | 每条必填 | "商务评审说明必须填写" |

选 06 的好处：该分支**不要求**技术分/商务分/价格分（jsf/swf/jgf）、
号球数（hqs）、下浮系数、技术商务评分表、总价量化表、多报价配置。
如果改选 07/08，就要多录一批表和分数，录入成本陡增。

价格硬约束：**合同估算价 ≤ 招标控制价**（`htgsjy` ≤ `zbkzjy`）。

## 容易踩的坑

- **长文本弹窗是追加不是覆盖**：内容重复会一起存进库，且字段有 2000/2048 字上限。
- **新建标段不会自动预填评审行**：本项目 `initData` 已被注释（`custom.jsp:349-351`），
  资格评审/形式评审必须手工点「新增」；换项目先确认这段代码是否还活着。
- **价格字段带 numberFormat**：界面上是 `980,000.00`，但 input 的真实 value 是 `980000.00`。
- **投标总价量化表 / 技术商务评分表在 06 下不需要**：不要被隐藏面板里的空表误导去补录。
- **形式评审第二信封（fhxscdexf）**：在部分评标办法/双信封模式下才会被要求，
  06 定性评审 + A01 实测不需要；报错才补。
- **保证金支付方式由后端固定写入**（`saveRootEntity` 里 setBzjzffsCode），不用手填，
  也不要拿代码注释里的中文说明去对码值——以代码为准。
- **仓库里的 `init.sql` 可能早于线上部署版本**：缺后来加的列、缺新表都常见。
  拼 SQL 前先用 `information_schema.columns` 确认真实表结构，别直接照抄 init.sql。
- **码表样例**（`0.编码表/*.ct`，`genDefaultCode="true"` 时按顺序生成 01、02、03…）：
  建设工程招标类型 `jsgczblx`：01 勘察 / 02 设计 / 03 施工 / 04 监理 / 05 咨询 /
  06 勘察设计 / **07 总承包** / 08 材料设备 / 09 质量检测 / 10 其他。
  建设工程标段分类 `jsgcbdfl`：**A08 工程施工**。
